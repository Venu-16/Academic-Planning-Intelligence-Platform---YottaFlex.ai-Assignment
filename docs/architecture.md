# Architecture

Generator (starter or configured target scale) -> relational/date/enum validation -> historical enrollment model -> chronological holdout evaluation -> course forecasts -> section planner -> OR-Tools CP-SAT faculty allocation -> section/assignment validation -> finalized lifecycle states -> operational-capacity and unmet-demand reconciliation -> run-scoped exports and state-transition events -> Streamlit dashboard.

Forecast MAE and RMSE are measured against the final historical term held out chronologically; the same observations are scored with a last-observation baseline. Forecast rows preserve target/source terms, the method, prediction inputs, eligible interest count, and fallback reason. Sparse-history and new-course behavior is explicit and deterministic. Report both metrics and do not assume the Random Forest is better.

PostgreSQL stores source tables, forecasts, sections, workload assignments, planned and operational capacity, unmet demand, planning runs and JSONB decision events. Source rows are upserted; run outputs use run-scoped identifiers and are retained so reruns do not erase prior results or audit events. Schema initialization adds capacity/run columns, lifecycle values, and not-valid term foreign keys to existing tables without deleting legacy rows; the new foreign keys enforce term validity for new writes without falsely certifying legacy data. The dashboard can select the configured output directory or completed report folders under `reports/`, and can query the latest persisted metrics. Set `TEST_DATABASE_URL` to a dedicated disposable PostgreSQL database to run integration tests; tests create and remove only a uniquely named temporary schema.

`--no-db` runs the pipeline without PostgreSQL for a fast smoke test. The starter optimizer handles faculty skills, availability, workload and faculty slot conflicts; room/time assignment is not jointly optimized.
